Technical nouns for this project:

- Operator: The person who does this procedure.
- ZIP: The supplied archive of project files.
- Package root: The extracted directory that contains README.txt and rust/.
- Material: A specified collection of chess pieces, with the two kings.
- FEN: A chess position record with turn, rights, counters, and board placement.
- WDL: A win, draw, or loss value from the viewpoint of the player with the move.
- WDL50: A Syzygy result that includes the fifty-move rule.
- DTZ: A Syzygy distance to a move that resets the halfmove clock.
- DTM: A distance to checkmate.
- Quiet move: A move without a capture or promotion.
- Zeroing move: A capture or pawn move that resets the halfmove clock.
- Oracle: A reference implementation or service used for a result comparison.
- Fiber: A group of positions with five fixed pieces and one variable square.
- Source row: One variable source square in a fiber.
- Packed mask: A 64-bit word with one bit for each square.
- Native Syzygy file: An unchanged .rtbw or .rtbz reference file.
- Working index: An index for GPU state, different from the native Syzygy index.
- Proof rank: A finite rank that supports a win or loss proof.
- Roofline: A performance ceiling calculated from arithmetic and data-transfer limits.
- Checkpoint: A saved solver state from which the solver can continue.

Technical nouns also include the standard chess, mathematics, computer, storage, and GPU terms below.
Product names, protocol names, file names, and identifiers are technical nouns.
Technical verbs include compile, decode, download, encode, extract, hash, parse, probe, profile, save, and synchronize.
These verbs refer only to their specified computer processes.

## 13. Keep the operator mathematics

Use separate packed masks for proven wins and proven losses.
Reject overlap between these masks.
Keep unknown positions different from draws until solver termination.
Cache legal-move existence separately from the dynamic result masks.

For a knight, let G be the shared 64-by-64 geometry matrix.
Let D identify the destinations that a move can use.
Let V identify valid sources.
Use these formulas for the shared tensor operation:

```text
B = D * (8 * [child != Win] + [child == Loss])
Z = G * B
winning_source = V & (((Z & 7) != 0) | (Z == 72))
nonwinning_source = V & (Z != 0)
```

The input values are 0, 8, and 9.
FP8 E4M3 represents these values accurately.
A knight has at most eight destinations.
If the eight destinations are all losses, then Z = 72.
The comparison with 72 keeps the loss information during the digit carry.

Use FP32 accumulation for the FP8 and FP16 comparisons.
Keep reduced-precision fast accumulation disabled in the first correct-operation tests.
Do not use FP8 with the first 0/16/17 value set.
FP8 E4M3 does not represent 17 accurately.

Compare the tensor result with the eight-shift knight operation.
Use physical blockers for bishop, rook, and queen operations.
Use fill distances of 1, 2, and 4 squares.
Apply king-safety masks to destinations.
Do not use unsafe intermediate squares as physical blockers.
Include captures through a separate dependency path.

- NOT IMPLEMENTED: The supplied or repaired program does not do the operation.

Do not classify BLOCKED or NOT IMPLEMENTED as PASS.
Record if the GPU operator program compiled and executed correctly.
Record if a GPU solver completed all legal positions in one material.
Record the largest material that passed the necessary comparisons.

Record which chess states and metrics the solver supports.
Record the cause and next necessary action for each incomplete stage.
Do not record a completed six-piece solver from operator measurements alone.
Do not record the eight-piece, one-hour target as achieved without a completed execution and the necessary checks.
