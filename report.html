Research design • 13 October 2026 UTC • CPU tests validate the reference rules. GPU performance is not measured.

A complete tablebase solver that can start on one H100 and grow across a GPU fleet

The proposed core is a factorized legal-move operator over packed state. This operator runs in shards that have a dependency order and independent checkpoints. Use segmented bit operations for ordinary moves. Use exact float reductions where shared relations make tensor cores economical.

Scope: this package is research on algorithm design and correctness. It is not a finished production generator or a generated nine-piece database. The code validates finite-graph WDL, bounded float predicates, toy clocked dynamic programs, and actual chess quiet-move relations. There is no CUDA GPU in the execution environment.

2. Public nine-piece progress

Lichess's 7 February 2026 announcement makes a precise nine-piece claim. Marc Bourzutschky computed selected op2 configurations with two pairs of opposed pawns and no other pawns. Any capture leads into an eight-piece op1 position. The post shows nine-piece examples from Carlsen–Aronian and Adams–Stefansson.

The public eight-piece op1 set is 63 TiB and covers approximately 5 × 1014 legal positions. It uses DTC, not the DTZ50 metric of Syzygy. Op1/op2 exploit closure under quiet moves and captures into solved smaller sets. This is real restricted nine-piece coverage, not a complete nine-piece tablebase. Our search found no credible public claim of a complete unrestricted nine-piece collection.

For our target, these techniques can give early milestones and dependency oracles. But they do not justify the exclusion of other nine-piece material or placements.

3. Define the exact target

Generate complete material closure: all legal moves, captures, queen/rook/bishop/knight promotions, pawn double pushes, en passant and supported castling-right states. Enumerated index slots can include illegal placements. Each such slot has an explicit validity predicate or mask. No heuristic may remove an unsolved valid position.

Separate (a) unclocked WDL/DTM, (b) a specified tablebase fifty-move model, and (c) strict FIDE clock claims. These have different values and should carry distinct format metadata. The common automatic-100-ply model is not identical to optional FIDE draw claims.

FIDE lets a player claim a fifty-move draw, and a seventy-five-move draw is automatic. Checkmate has precedence over these draws. An exact clock-claim operator adds a draw action when a claim is possible, and uses the 150-ply automatic boundary. The board, rights and halfmove clock do not contain arbitrary earlier repetition history. A probe engine that knows the history must supply it. Otherwise, a separate history-state solver is necessary.

The prototype tests both the automatic-clock model and a toy optional-claim/automatic-deadline model. It does not implement a complete chess repetition-history graph. See FIDE rules and the formal model in ChessTB's correctness document.

4. Dependency order turns the clocked core into a DAG

potential(position) = (piece_count,
                       total remaining pawn advances to promotion,
                       number of retained castling rights)

Capture, pawn move, promotion or loss of rights: decreases potential.
Other quiet moves: same potential, same pawn placement and rights.

Clocked state: (position, halfmove_clock)
Quiet move: clock increases.
Zeroing move: clock resets, but potential decreases.

The pair (potential, time left before the automatic draw) decreases along every nonterminal transition. Thus the defined clocked game is acyclic. Solve smaller potential first. Then solve each layer from the deadline clock down to zero. This replaces convergence at an unbounded mate depth with a bounded clock dynamic program. Castling exits decrease rights but do not reset the clock, and the solver must keep that distinction.

For WDL alone, outcomes at successive clocks often admit a decisive/draw threshold under the chosen semantics. A stream implementation holds only the current and next clock planes. It can encode outputs losslessly as change points. Do not assume arbitrary distance functions have one threshold: exact mate distances may have many changes.

Unclocked WDL and long DTM still must use the attractor/fixed-point stage. When the clocked phase finishes, keep that stage if the output contains cursed wins and blessed losses. A complete metric package contains stages with separate definitions and verification.

5. Factorized move groups

Fix every piece except one piece that is not a king, and vary its square across up to 64 cells. Read the opposite-side-to-move W/L values for those cells as packed words. For quiet moves, the legal relation factors into source validity, movement geometry through fixed blockers, and a destination-only own-king-safety mask.

For rook, bishop and queen moves, fixed blockers split ranks, files and diagonals into segments. All distinct empty squares in the same legal segment are mutually reachable. Masked segment reductions find if any child loses and if any child does not win. These reductions exclude the source square. One operation reuses occupancy and legality across many placements. It does not decode and rank each successor independently.

Knights use a fixed jump stencil and legality masks. Kings use a separate attacked-square operator and canonical king-slice mappings. Captures, pawn moves, castling and promotions are boundary operations, and the slider kernel does not silently absorb them. Identical pieces must use a canonical set index. A temporary expansion of a tile into labelled square groups is safe only under two conditions. Each result must map back exactly, and the solver must combine duplicate orbit updates.

Validated: 160 actual chess groups, 7,426 legal source rows and 48,842 quiet edges matched python-chess. Of these, 5,369 source rows were slider cases, and their segmented relation matched the legal-move relation exactly. This result shows those sampled local identities. It does not show that the production index is correct for all positions.

6. Exact float optimization

Let L(y) show a child that loses and W(y) a child that wins. For a reduction with at most 64 destinations, encode:

E(y) = 65 * (1 - W(y)) + L(y)
       = 0 for a winning child
       = 65 for an unresolved/drawn child
       = 66 for a losing child

z(x) = sum_y legal(x,y) * E(y)
     = 65 * nonwinning_count + losing_count

any losing child      <=> z % 65 != 0
all children winning  <=> z == 0, and legal degree > 0

Inputs 0, 1, 65 and 66 are exactly representable in FP16 and BF16. A bounded sum is at most 4,224, so FP32 accumulation represents every possible sum exactly. Decode each bounded reduction before you combine flags across larger groups. If you sum encoded results first, a radix carry can hide children that lose. The test suite contains a test for that regression.

Store permanent state as bits. Unpack only an active tile into FP16/BF16. Compute on that tile. Then repack it immediately. Do not store the full table as floats.

FP8 cannot directly represent this 65/66 code. Thus FP8 must use a different proven code or separate binary queries. NVIDIA also documents an implementation detail with reduced precision for some accumulation modes of FP8 WGMMA. Validate the actual instruction path that you choose. Do not infer exactness from an FP32 output dtype.

An FP16 matrix row uses 128 bytes of adjacency for each 64-destination query. A packed bitset row uses only 8 bytes. Without reuse, a tensor-core formulation can lose on memory and pack costs, even when arithmetic is fast. Native tile padding is another cost: a single useful query column does not fully use a 16-column dot tile. Group relations only when they are genuinely identical and several useful state vectors share them. The included GPU benchmark reports queries=1 and queries=16 separately.

NVIDIA PTX ISA specifies FP16/BF16 accumulation precision. The bounded-integer exactness argument is our inference from those semantics. The CPU reference emulates FP16 operands with FP32 accumulation. Tests on hardware must still check actual tensor-core behavior and speed.

7. Shards that survive retries and scale beyond one machine

  1. Deterministic ownership. Use a shard key with rule/format version, material, pawn placement, rights state, king slice and the range of other coordinates. Split ranges to fit a memory target. Do not assume that every material has uniform size.
  2. Move-aware cache. Prefer adjacent king/pawn/anchor slices. Stream one boundary input at a time. Accumulate proof flags. Keep hot pages in memory during a local closure. Measure useful bytes and misses per proved state.
  3. Adaptive work representation. Sparse sorted IDs for small deltas, runs/compressed bitmaps for clustered deltas, raw bitmaps for dense deltas. A 64-bit ID list becomes larger than the raw two-bit-plane payload near 3.1% density. This point does not include list headers and route costs.
  4. Idempotent updates. Send proved value bits and dirty notifications. OR combines duplicate proofs safely. Do not use unguarded counter decrements on at-least-once delivery. A loss proof must check all legal successors against valid child values. It must not use an empty queue as proof.
  5. Safe commit. Write new immutable blocks and their checksums. Then conditionally advance the generation of the owner manifest. Record dependencies, rule version, input hashes and open epochs. Failed/stale workers cannot overwrite a newer result. The system must have atomic conditional writes in the object store, or a transactional control database.
  6. Termination. A clocked DAG layer finishes only after the commit of all its input dependencies and assigned ranges. A fixed-point layer finishes only after a real distributed termination protocol drains all its work. This work includes shards, outbound/inbound messages, dirty sets and in-flight leases.
  7. Distance and verification. Keep clocked DP values and unclocked proof ranks distinct. Asynchronous WDL discovery order is not DTM. Use ordered waves or a separate exact distance relaxation. Then verify coverage and certificates before you publish table files.

The CPU asynchronous model handled delayed, duplicate notifications across 1, 2 and 7 simulated owners. It matched an independent counter-based oracle. It models globally visible values. It does not benchmark a real network or implement the production commit protocol.

9. Benchmark-driven implementation sequence

  1. Make sure that production chess/index code is correct on 3–5 pieces against available trusted WDL and distance files. Include all special-move tests.
  2. Run the supplied packed-bitset and exact-FP16 microbenchmarks. Add end-to-end measurements of relation generation, rank calculation, transposes and boundary probes.
  3. Implement warp-per-group slider segment reductions and knight stencils. Keep a scalar legal-move fallback for every unsupported case.
  4. Generate all six-piece material tables with complete dependencies. Verify them independently. Record per-class elapsed time, physical I/O, peak memory and exact coverage.
  5. Demonstrate seven-piece external-memory generation with restart/duplicate-work injection. Compare hot-cache and cold-storage operation.
  6. First, scale by independent material/pawn layers. Then distribute large quiet components. Same-node NVSwitch and cross-node commodity network links must use distinct route policies.
  7. Complete eight-piece dependencies before you claim general nine-piece coverage. Op2 can be an early milestone for nine-piece verification. But it does not replace unrestricted subtables that are not present.

Modal GPU functions and Modal multi-node clusters can host workers. Confirm platform access and network setup before deployment. GPU sandbox workers on other providers can use the same immutable shard protocol. Do not assume NVLink between separately scheduled workers. This research did not launch a remote GPU instance or use a paid service.

10. Validation and open work

The supplied validation passed 120 cyclic graphs, 12,720 random-graph nodes and 22,941 duplicate notifications. It also passed a 256-edge forced chain, a radix-carry regression and 160 actual chess groups. Three clocked-DAG cases passed, and one of them has a 150-ply deadline/100-ply claim threshold. The independent counter oracle and the float fixed-point solver agree. Certificates check terminal anchors, win/loss proof ranks that decrease and defensive draw closure.

Some implementation risks remain. They are production index and symmetry boundaries, all special moves, rule compatibility and external dependency access. Asynchronous distance correctness, real transactional checkpoints and hardware throughput are also risks. Only full coverage counts plus independently checked proof/distance evidence justify the publication of a solved tablebase.

The best candidate is a hybrid solver with segmented bitsets and exact float reductions. It uses dependency-ordered clock DP, and asynchronous packed frontiers for the unclocked stage. It keeps complete coverage. Future hardware can change tile sizes and the schedule, but the game semantics do not change.

11. Whole-collection budgets: the one-hour target is not met

The per-material capacity table above is not a budget for the full collection. NULP counts 38,176,306,877,748,245 canonical locally legal eight-piece positions with its stated special-right conventions. This is an enumeration model. It does not prove that each state must have separately stored bits, or that every state is historically reachable.

To enumerate that domain in one hour, a solver must process 10.60 trillion states/s. At the peak HBM bandwidth of an H100 SXM, 3.35 TB/s, the budget is only 0.316 physical bytes/state. A conventional dense sweep reads and writes two bits for each state, which is 0.5 bytes/state. At peak bandwidth, that sweep takes at least 95 minutes. This time does not include move calculations or more sweeps. This is a conditional bound for that representation, not an impossibility theorem against a symbolic algorithm.

To write 1.5–2 PB of final output in one hour, the destination must accept 417–556 GB/s. If all output crosses an assumed 64 GB/s one-direction PCIe 5 link, export alone takes 6.5–8.7 hours. CPU-side expansion can bypass that GPU link but cannot reduce the necessary throughput for the final output. R2 gives no guarantee of this aggregate upload rate. This work did not measure an H100 or live R2.

The figure $22,500 was a monthly R2 price for 1.5 PB, not a claim of 22 PB. Decimal PB and binary TiB are different units. A two-bit array over the NULP eight-piece count occupies about 9.54 PB. That is an illustrative raw representation. Do not confuse it with compressed files for distribution.

Inspection of the Syzygy source shows combinatorial equal-piece indexes and board/color symmetry. It also shows five WDL outcome classes in .rtbw files and DTZ data in .rtbz files. Compression builds a hierarchical dictionary from adjacent symbol pairs and Huffman codes it, with block indexes for point queries. A domain with one constant value can use a single-value marker. The prober reconstructs capture results, so selected stored cells can become compressor-controlled fillers. The format can store distance information for one side and reconstruct it for the other.

ChessTB adds probe-time reconstruction. It can omit a side-to-move frame and rebuild it by one-ply minimax. It can also store loss distances and reconstruct win distances from children. You cannot combine these choices arbitrarily, because they can create circular dependencies.

In ChessTB, capture/promotion bounds free some WDL cells to take compressor-friendly values. Boundary markers must stay. The format can omit DTZ=1 win cells where a zeroing move reconstructs them with the same value. The format uses independent LZ4-HC/dictionary WDL blocks and frequency-ranked LZMA distance blocks.

Precision qualification: ChessTB documents that its one-byte tier can make cursed/blessed DTZ distances coarser by up to one ply. Thus its reported distribution size does not guarantee byte-for-byte equality with an arbitrary exact-distance target. Our strict-distance mode must keep the original ply values. In contrast, the DTM parity method that stores half values is lossless. Extra castling WDL+DTZ files add about 704 GiB in the reported ≤7 collection.

Research on decision DAGs, MTBDDs and logic minimization is relevant. But the ECAI paper found Syzygy most compact on its tested tables. Logical representations can improve query time. These experiments start with solved labels. They do not show a shortcut to generate every eight-piece outcome.

13. Measured exact experiments and the compression direction

The new exact group prototype computes strong bisimulation. In each group, terminal labels agree and each member has the same set of successor groups. It keeps WDL and DTM. It passed 32 random cyclic graphs. It also reduced a constructed 640-state repeated graph to five groups.

On complete canonical KQvK, it was much less successful. 46,138 nodes, with the capture draw sink, became 45,249 groups, only a 1.020× reduction. It kept 606,868 of 609,873 edges. Refinement and solution took about 1.22 s, compared with 0.27 s for the ordinary sparse oracle after graph construction. This is a negative result. Do not adopt this group method as the performance improvement.

All 46,137 KQvK board positions independently matched the published Syzygy WDL table. Maximum DTM was 20 plies. A domain-specific geometric WDL predictor also matched every position. A legal black queen capture or a source stalemate gives a draw, and otherwise the stronger side wins. This covers the tested standard KQvK board domain with a fresh clock. It does not cover arbitrary clocks, and it is not a theorem for larger materials.

A research direction with good potential is a deterministic outcome predictor plus an exact exception index. Each block independently selects that representation, symbolic rules or conventional Syzygy-style codes. Lookup returns predictor(position), but an exception overrides it when present. Exactness must come from complete certified coverage of the exceptions, not from a sampled accuracy score. Distance layers must have separate exact residuals and boundary logic. A learned predictor alone is not an exact tablebase.

For illustration only, assume that an eight-piece outcome predictor has error fraction ε. Ideal exception-location entropy plus a two-bit exception value then costs N[H₂(ε)+2ε]/8 bytes. At ε=10⁻⁴ this is about 7.98 TB, and at ε=10⁻⁶ it is about 112 GB. These hypothetical numbers exclude model size, random-access indexes, distances and proof metadata.

No such eight-piece predictor or exhaustive certification exists. The difficult research problem is to prove large outcome regions without enumeration of their individual states. A tiny final representation alone does not solve generation.

14. R2 format and validated storage prototype

The included r2_blocks.py implements a local storage format for research. It has two-bit ordinary WDL, independent Zstandard pages, per-frame checksums and content-addressed grouped objects. It also has indexed range reads, batched query groups and an LRU cache. Default raw pages cover 262,144 positions (64 KiB), and object targets are 1 GiB. A read-only S3 range adapter can accept an external client. This is transport/storage infrastructure, not an improvement over Syzygy compression, a fifty-move table, or a completed cloud service.

The local test round-tripped all 69,635 positions and checked 10,000 random queries. It grouped 18 frames into three objects, rejected invalid IDs and detected corruption. The test used no credentials, no R2 upload and no live cloud query.

15. Actual compression improvement with a chess prober that works

For each block, the exact adaptive codec selects constant values, offset/palette codes, bit planes, lag residuals or predictor-plus-exception streams. Candidates include raw, Zstandard and LZMA forms, and the selection counts the full frame with its 32-byte integrity header. The current TBC2 extension keeps signed 64-bit values with raw, XOR-lag and byte-plane codes. Narrow pages keep TBC1. The codec does not round values.

A narrow predictor is optional and has a hash check. The codec stores every correction. This work did not train or certify an eight-piece predictor.

The full native KQvKR WDL streams contain 3,822,504 stored index slots. These slots include the illegal/capture-resolvable fillers that the Syzygy compressor selected. Every stored symbol round-tripped. At 65,536 cells/block, adaptive frames used 21,302 bytes, compared with 25,342 for the same-frame packed-Zstandard baseline. This is a 15.94% reduction. But this first result was still larger than the published 20,496-byte file.

The earlier v2 experiment at 262,144 positions per block used 17,586 bytes. This total includes object data, authenticated indexes, root manifest and chess metadata. The current v3 archive adds per-frame authentication and binds the chess index and rules into the catalog. Its size is 18,224 bytes, about 11.09% smaller than the published 20,496-byte KQvKR WDL file. This is one complete four-piece material, not a full four-/seven-/eight-piece set. It does not justify a reduction of the projected eight-piece size by this percentage.

native_wdl_bridge.py reuses the canonical rank function and capture-resolution semantics of python-chess with our range-readable symbols. It does not open the original KQvKR WDL payload. It matched 2,500 legal FEN probes, with color mirrors, against the original Syzygy files. It also matched 100 DTZ probes, but these probes still used original local DTZ data.

The batch read 3 archive ranges with a total of 16,776 bytes. A repeat of the batch did zero archive reads. Route and chess metadata were already in memory. Other-material dependencies remain local. The bridge uses private python-chess interfaces pinned to chess 1.11.2.

The KQvK exact DTM experiment also verified the reconstruction of all win distances from loss distances only. It also verified the lossless parity method that stores half values. Its full distance value stream compressed to 16,208 bytes, and the parity-halved loss values used 4,724 bytes. Those numbers exclude the loss-entry index and WDL metadata, and are not complete-file savings.

Reconstruction of wins inspects children, so a storage reduction can increase lookup work. Keep that tradeoff explicit. Batch child requests.

17. Fast lookup with fewer paid origin requests

  1. Compute the route and the canonical rank locally. Cache versioned material/metric route metadata. A production catalog must have hierarchical material/range directories. It must not load a full all-eight catalog or call ListObjects for each query.
  2. Page the index. Current v3 objects carry 32-byte offset/length/inline-value/checksum records. Legacy v2 uses 16 bytes. A small authenticated directory hashes index pages. Fetch only the relevant pages, not the full index of an object. Index and directory caches have explicit byte budgets.
  3. Batch legal children and user positions. Find absent symbols across the batch. Read the unique necessary blocks. Then continue exact capture/minimax resolution. Never change a value because a dependency is still absent. WDL and distance requests can have different dependency waves.
  4. Merge nearby ranges. Use one contiguous GET for a cluster. The default planner caps a cluster at 1 MiB, 4 KiB gaps and 2× byte amplification. This method uses ordinary single-range requests, which R2 supports. It does not assume a multipart-range API. Optional bounded parallel reads hide independent miss latency.
  5. Cache and deduplicate. Keep decoded hot blocks and metadata near the prober. SingleFlightStore joins concurrent identical immutable range reads and caches returned bytes. Its test collapsed 16 simultaneous callers into one storage read. It also verified a retry after failure.
  6. Use an edge cache for immutable ranges. range_worker.mjs gives a read-only R2 proxy and joins identical in-flight reads. It wraps a range as its own HTTP-200 resource with a content-addressed cache key. The Cache API of Cloudflare rejects direct 206 puts and is local to a data center. It does not give a tiered cache. This implementation is mock-tested, not deployed.

A cache hit removes an R2 origin operation. But it does not always remove the client request or Worker charge. Workers Standard has a $5 monthly subscription, 10M included requests then $0.30/M, and 30M included CPU milliseconds then $0.02/M CPU-ms.

For illustration, 100M single-position API requests at an assumed 5ms CPU each cost about $41.40 for Workers. With one data block each and no cache hits, R2 adds $32.40 after the read allowance. At an assumed 99% block hit rate, the one million GETs that result fit in that allowance. These totals exclude data storage, writes, logs, other services, nonresident metadata and dependency expansion. They are rate-model scenarios, not a deployed service quote.

For minimum storage cost, put genuinely cold immutable payload in Infrequent Access. Keep hot data/metadata in Standard plus local/edge caches. IA cuts the listed storage rate from $0.015 to $0.01/GB-month. But it adds $0.01 per billable retrieved GB, higher operation rates and a 30-day minimum.

If you ignore operation differences, IA costs more when billable monthly retrieval is more than half the stored bytes. Billable retrieval bytes and cache hit rates must come from observed usage. Do not assume that a tiny logical return value means tiny backend retrieval.

At the old 1.5–2 PB projection, all-cold IA storage alone is $15,000–$20,000/month compared with $22,500–$30,000 for Standard. These numbers exclude retrieval and hot copies. This is a scenario for storage tiers, not a smaller generated dataset. Optimize compression first. Then choose the storage class from access traces. This work did not show one-hour H100 generation or a compression improvement for the complete eight-piece set.

19. Edge cases and exact state boundaries

Current storage tests cover signed 64-bit extremes, zero-length frames, partial final pages, all codec modes and padding. They also cover decompression limits, predictor mismatches, corrupted indexes/frames and failed stream publication. The tests also cover capped range reads and IDs above 253.

JSON transports large integers as decimal strings. Rust parses position IDs directly into integers. The one-pass Python publisher first fsyncs the immutable payload and content-addressed chess metadata. It commits its root only after that. Source-symbol caches bind to both source-table and cached-array checksums. Corruption forces re-extraction.

The chess suite checks 400 standard/Chess960 board snapshots, 16 repetition-claim states and 2,832 WDL positions. It checks 418 en-passant cases, and 60 of these EP positions change the value. It also checks all four promotions, capture promotions and cross-material deferred dependencies. A separate 5,000-position KNNvKP sample exercises all five published WDL classes, with cursed wins and blessed losses. The suite also tests sixteen concurrent batches, companion-metadata corruption, invalid query cleanup and closed sessions. These are finite regression suites, not an exhaustive proof of all chess positions.

Board snapshots keep turn, placement, promoted flags, raw EP, castling rights, Chess960 mode and counters. Game-context records keep repetition counts and an explicit history-completeness flag. This represents the necessary context. It does not implement a castling tablebase or solve a full FIDE repetition-history graph. WDL archives carry the published Syzygy reset-clock semantics. FEN alone cannot certify a complete earlier history.

20. Packed lookup and stable physical ranges

The authenticated v3 path keeps packed pages and extracts only queried cells. It does not expand a full block to int64 or rehash all decoded values at each lookup. Its trust contract is explicit: the publisher must fully verify decoded pages before it authenticates encoded frames. Legacy v2 keeps full decoded-checksum verification. Shared cache identities use immutable object hashes, not material-local ordinals. This prevents cross-material collisions.

The test used the local complete KPvKP archive and a synthetic uniform trace of 128 batches and 2,048 queries. It had a 128 KiB page cache and a 1 MiB compressed cache. With stable 16 KiB physical tiles, Python origin reads went down from 1,104 to 13. The compressed working set was 198,506 bytes and fit in cache.

Clustered traffic sometimes transferred fewer bytes with ordinary coalesced ranges than with aligned tiles. Select alignment from measured locality. These results do not imply a full-eight hit rate or cloud latency.

21. Rust and current NVIDIA cuTile

Rust is the production implementation target. The tested rust/ project gives an exact page encoder and a selective authenticated page decoder. It also has a legacy/v3 native-ID archive reader, a sorted/deduplicated batch planner and capped range reads. Other parts are global byte-budget caches, aligned physical tiles, concurrent single-flight and a finite-graph WDL oracle. Its own CPU code forbids unsafe.

Python remains the independent oracle and current archive publisher/FEN adapter. The Rust CLI now probes native archive IDs. The custom v3 FEN adapter stays in Python. SIX_PIECE_SPEC.md describes the newer native Rust FEN reader. The complete GPU generator is not implemented yet.

The Rust suite reads 402 independent Python codec fixtures that cover ten modes and three compressors. It rejects 3,216 encoded-frame mutations and compares 10,000 v3 and 10,000 legacy native chess IDs. It tests 100 independently solved graphs and enumerates 65,536 loss-mask predicates. It also joins 16 concurrent tile requests into one origin read. Reverse interoperability checks feed Rust-encoded frames back into the Python decoder. Format checks, Clippy and release tests are reproducible from bundled sources and fixtures.

A Rust cache-pressure trace of the same size reduced local origin reads from 1,355 to 13. With alignment, it read 198,506 bytes. The file rust_cache_benchmark.json records its independently checked timings. The Rust and Python traces and their cache statistics differ. Thus these results are not a controlled comparison of language speed. Local filesystem times also exclude cloud transport, and the OS cache can make them faster.

NVIDIA/cuda-rust now gives both cuTile and cuda-oxide SIMT kernels over a shared runtime. The GPU project pins revision bc46b1ffb751885073066b087594045f07f0f81b. Use Tile for regular dense operators. Evaluate SIMT for irregular move generation and frontier traffic.

Hopper Tile IR 13.3 is necessary for the upstream code. The inspected README recommends CUDA 13.3. Our attempted GPU build stopped in cuda-bindings because no CUDA toolkit is installed. The supplied kernel is formatted but its host/JIT compilation and H100 execution remain unverified.

The Rust GPU microbenchmark first validates exact 64-child bitmask predicates. Then it measures the time for one million synthetic resident rows. It excludes move generation, rank calculation, dependency traffic, compression and the distance solver. Its nominal traffic of 32 bytes per row is a synthetic model, not measured HBM bandwidth.

With more than 64 children, combine blockwise results: OR gives the win predicate and AND gives the all-children-win predicate. FP16/FP32 reductions are an optional experiment with bounded exact arithmetic. Use them only when useful shared relations and measured throughput justify them.

Frontier target remains unmet: a language/toolchain choice and fast local lookup do not show complete eight-piece generation in one hour. The package contains no complete eight-piece generator, no H100 throughput result, and no measured complete-eight compression factor. The next hardware milestone is an end-to-end small-material solve with independent verification against published tables. This solve must include index calculation, legal moves, promotion/EP closure, transfers, compression and durable output.
